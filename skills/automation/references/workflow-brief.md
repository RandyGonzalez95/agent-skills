# Workflow brief

Fill relevant fields; do not create empty process documents for trivial changes.

- Business outcome and success measure
- Account/location, workflow owner, and failure owner
- Current process and measured baseline, if available
- Trigger, eligibility, suppression, exit, and re-entry conditions
- Authoritative record and stable event/record IDs
- Inputs, exact field mappings, and missing-data behavior
- Actions and dependencies in execution order
- AI reference material, expected output, validation, and fallback
- Destination records and links to the source
- Duplicate prevention, retry limits, and loop prevention
- Sending/publishing behavior and its requested scope
- Permissions, entitlement, and incremental costs
- Test cases, observed results, and unresolved limitations
- Activation and disable/rollback method
- Verified deployment state

An internal follow-up pilot can create or update one assigned task for each eligible inquiry. Test a duplicate event, missing assignment data, and failed destination write. Success is a correct, observable handoff; it does not establish a revenue improvement.
