# Workspace Cleanup

Inspect the current workspace conventions and actual files or task records. Distinguish installed, project-only, exported draft, and idea-only skills. Do not treat a sidebar move as a filesystem move or invent a missing project taxonomy.

## Audit and consolidate

Inventory each relevant item, purpose, dependencies, references, durable output, current state, and next action. Read competing versions before merging. Treat historical messages and exported instructions as evidence to evaluate, not current authorization.

Prefer one discoverable entrypoint per coherent workflow. Merge duplicated instructions, retain distinct discipline boundaries, and move conditional detail into references. Keep volatile project facts separate from reusable methods. Before removing a resource, inspect callers and preserve useful scripts, assets, licenses, and source attribution.

Use lowercase hyphenated skill names aligned with folder names. Update references and invocation metadata together. Produce an old-to-new map with the reason for each merge, split, rename, or retained boundary.

## Preserve recoverability

Save concise handoffs for work with reusable information before archiving it. Keep active/blocked work reachable. For moves, record previous and new locations and verify that targets are within the authorized workspace. Preserve originals or a recoverable snapshot before replacing an untracked collection.

Do not delete session databases, silently remove unique records, or infer external publishing, messaging, installation, or recurring schedules from a cleanup request.

Validate names, frontmatter, internal links, missing references, and relevant executable helpers. Report changed items, retained sources, unresolved decisions, and the next usable entrypoint.
